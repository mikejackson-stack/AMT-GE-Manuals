Doing the Controller Area Network (CAN) Link Diagnostic

The Controller Area Network (CAN) Link Diagnostic does a read-write test on any available nodes on the Controller Area Network (CAN) network.

Topic ID: id_SL1908978-1224935

Diagnostic link

Diagnostics > System Function > Patient Handling > CAN Link Diagnostic

(For ICE Config) Diagnostics > Hardware Location > Misc > CAN Link Diagnostic

(For CAM Config) Diagnostics > Hardware > PGR Cabinet > CAM > CAN Link Diagnostic

Topic ID: id_SL1908979-1224935

Purpose

The CAN Link Diagnostic does a read-write test on any available nodes on the Controller Area Network (CAN) network.

CAN is a communications layer that is used to communicate serially to nodes over a high speed data layer. The CAN network uses a protocol called CAN open to communicate with its peripherals, or nodes. Each node has a unique node ID (1-31), which helps determine where each message is sent.

This test detects any available nodes on the link by listening to the network and then determines which nodes are available based on their Node IDs. Once the nodes are identified, a walking ones pattern is sent to each node and read back to verify the communications link. The test can be set to run several iterations to help find any intermittent failures.

Use the Force Reset button to force a reset of the nodes before running the test to put all of the nodes in a known normal state. The test should be first run without the reset to determine if any nodes are in a bad state. The Force Reset button should only be used as a fallback to bring the nodes back to a normal state.

Topic ID: id_SL1908980-1224935

Components tested

The nodes that are available for detection using this test are:

  • Driver Module (Node ID 2)
  • RF NB Amp I/F (Node ID 7)
  • SRI (Node ID 11)
  • RF Amp (Node ID 24)
  • CFB (Node ID 20)
  • ASC BB IF Board (Node ID 6)
  • ASC RF Processor 1 (Node ID 8)
  • ASC RF Processor 2 (Node ID 9)
  • RF Hub (Node ID 28)

Requirements

None

Topic ID: id_SL1908994-1224935

Test sequence

The CAN Link Diagnostic first detects all of the available nodes on the CAN link by monitoring the Node Guarding messages.

  1. On the CAN Link Diagnostic page, enter the number of times you want the test to run in the Iterations field.

    The test can be set to run several iterations to help find any intermittent failures.

  2. Click Run.
  3. As nodes are detected, they are logged on the screen and then a data path test is run on each of them sequentially. The data path test consists of writing a walking ones pattern in the Diagnostic Dictionary Index on the node and then reading it back.
  4. The received data is checked to make sure it is valid. The data path test is repeated three times on each node. Any errors will result in an error message being logged and the information written to the screen.
Note If Force Reset is selected, all CAN nodes are reset prior to monitoring the Node Guarding messages. This is used when a reset is required to put all of the nodes in a known normal state. The test should be first run without the reset to determine if any nodes are in a bad state. The Force Reset button should only be used as a fallback to bring the nodes back to a normal state.
Topic ID: id_SL1908995-1224935

Expected results

The CAN Link Diagnostic compares the nodes that are detected against the system configuration and emulation settings. All nodes that are detected, configured, and not emulated are tested and the test results are shown.

A status message indicates any nodes that were not tested but were detected and/or configured. This list gives the reasons for why a node may not be tested.

  • Not detected
  • Not detected - Node configured and emulated
  • Not tested - Node detected but configured and emulated
  • Not tested - Node detected but emulated
  • Not tested - Node detected but not configured

If any configuration or emulation result is shown, make sure the configuration of the system is correct and that no emulations exist for that node.

  • Driver Module powered off
  • (For CAM Config) CAN Terminator not installed on the SCP
  • CAN Terminator not installed on the last node on the CAN link
  • Not all nodes connected on the CAN link, including SCP, or CAN cable disconnected
  • System configuration incorrect, if only some nodes not detected
  • (For CAM Config) SCP or CAN PMC failures. Run the CAN datapath diagnostic to verify SCP to CAN PMC communication
