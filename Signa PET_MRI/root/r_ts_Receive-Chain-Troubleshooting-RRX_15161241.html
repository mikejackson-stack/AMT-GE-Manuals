Receive Chain Troubleshooting (RRX)

Topic ID: id_SL15164262-1127370

Disclaimer

Systems using software version 30 or later will use either the RRx receive chain or the DPP receive chain. To determine receive chain type, check the Receiver Type field in the Hardware Configure tab of Guided Install. RRx indicates the RRx receive chain, and DPP indicates the DPP receive chain.

Topic ID: id_SL4165283-1127370

Receive Chain Faults

A typical receive chain fault looks like the following example.

  1. Use the multicoil bias tool to confirm faulted channels. (Troubleshooting > Diagnostics > Hardware Location > Magnet Room)

  2. Use the coil datapath diagnostic (CDD), which uses the MCRv tool to isolate receive chain components. (Troubleshooting > Diagnostics > Hardware Location > Magnet Room)

  3. Use MCQA to identify coil image quality issues.

Topic ID: id_SL4165284-1127370

Available Receive Chain Diagnostics

Depending on the fault troubleshooting, use the appropriate diagnostics to help isolate the root cause.

Note

In addition to Diagnostics, the proprietary extended error message visible from the GE System Log located under the CSD Error Log tab will also help with isolating the issue. Often, the problem can be isolated by performing an action, performing a TPS Reset, and then checking system error log for changes in message content.

RF Hub Front View

Inside RFSB:

  • Signals amplified (R1 adjusted)

  • Signals down-converted to 16MHz

  • Signals switched and routed

  • Multicoil Bias from MCDB on each receive channel

Inside MCDB:

  • Provides DC Bias to control PIN diode circuits used as part of the decoupling network for multi-coil arrays

  • Bias is sent to RFSB via backplane for P-Ports

  • DC Bias Fault detection

Inside RFCB:

  • Coil Interface Support:

    • Read and validate Coil ID from ports

    • Deliver preamp power for coil ports

  • Provide multicoil bias to legacy coil port A

  • Distribute the local oscillator (LO) and exciter loopback to RFSBs

  • Monitoring for a multicoil bias driver

  • Interfaces with dock status to relay P-port status

  • Detects status of quick disconnect plugs

  • Contains mux select bits that are needed for internal coil muxing

Inside PDBv:

  • The PDBv generates specific voltage levels and distributes them to each of the following hub boards:

    • RF switch select board (RFSB)

    • RF control board (RFCB)

    • Multi-coil driver board (MCDB)

  • One PDBv can be used in the RF hub to support up to 32 MR receive channels

Example of a Bad Channel

Symptom: Poor image quality or low SNR using 8 HR brain coil

Scanning a phantom in GESERVICE Mode – using the saveinter CV to view all intermediate images as well as the combined image (9 images in total) – indicates that image 4 has no (or little) signal.

The 8 HR brain coil uses the legacy A-port connector. On a system that does not have a reroute box, this connector connects directly to the RFSB in slot 13.

  1. Use the MCRv tool to decide if the coil or receive chain is suspect. If the MCRv tool is not readily available, use another 8 channel coil that uses the A-port.

  2. If you have decided that the coil is good, and the issue is somewhere within the receive chain:

    1. Swap both cables (J1 and J2) between receiver 1 and receiver 2.

    2. Re-scan the 8 HR brain coil using the saveinter CV.

  3. If the failing image now is GOOD and all 8 intermediate images look good, suspect receiver 1.

  4. If the failing image is still BAD, the receiver is good. Suspect the RFSB.

    1. Swap RFSB1 with RFSB 2.

    2. Re-scan the 8 HR brain coil using the saveinter CV.

  5. If the failing image now is GOOD, all 8 intermediate images look good. Suspect the RFSB 1 board.

  6. If the failing image is still BAD, call your support team member or OLC for additional help.

Topic ID: id_SL4165807-1127370

TPS Reset Fails Due to Receive Chain Loopback

During every TPS reset, the RRx chain runs a loopback test to calibrate each receive channel for each R1 setting.

The loopback test stores a log file in the /usr/g/service/log directory.

The log file is named r1GainCal_date.dat (for example, r1GainCal_2011Sep14_12_28_42.dat).

For each R1 value, for each channel, the measured energy drops by 3db ± 0.5db. If a channel falls outside the tolerance, the pass/fail column will indicate fail for that channel. No entry indicates pass.

The log file continues to R1 value = 1.

Example:

Review the loopback cal file:

  1. Open a C-shell.

  2. Type ls –altr r1Gain*.

    This command will list all of the R1GainCal files with the most current file shown on the last line.

  3. Display the contents of the log file (use more, gedit, or view to display the contents of the file).

Diagnosing the Issue:

  • The example file above shows channel 6 fails for both R1 of 13 and R12. (In this case, channel 6 fails for all R1 values. The remainder of the log file is not shown.)

  • During R1GainCal loopback, the same exciter signal is distributed across all channels. Having only one channel fail suggests the exciter is NOT the issue.

  • Because the RFSB is responsible for setting correct R1 values, the RFSB would be suspect. However, it is best to run diagnostics and follow the same troubleshooting steps shown in Example of a Bad Channel to confirm.

Topic ID: id_SL4176224-1127370

Intermittent Multicoil Bias Faults

If the system is experiencing intermittent multicoil bias faults, try running a scan with and without RF enabled to see if there is any difference. Noise may be entering the bias lines (possibly from a loose quick disconnect).
