Troubleshooting BrainWave on Console

Topic ID: task_ntn_3d2_55b

General

About this task

  1. The third-party audio/video system must be powered on before the host PC is powered on for Brainwave video to work.
  2. Third-party hardware must be powered on prior to the host being powered on.
  3. The in-room monitor must be configured for Brainwave video to work.
Topic ID: task_rmx_2zg_ytb

Audio stimulus

About this task

  1. To check the audio stimulus, use the autovoice feature to isolate audio-related issues between the host PC and BrainWave/third-party hardware.
Topic ID: task_brz_lzg_ytb

Visual stimulus

About this task

  1. To check the visual stimulus, disconnect the PXE VGA cable from the host PC, and connect it directly to the spare VGA port on the workstation monitor.
  2. Open the command prompt and execute xterm -display :1.1 to open a terminal window on the VGA output.
    Note: The Shell window can only be launched when the EA3 user is included in the authorized EA3 group. Users not in this EA3 group will not have access to launch the Shell window. If you are not logged on as the proper logon user, log out and then log back on as the correct EA3 user with the authorized permissions.
    Note: If the MR workstation monitor does not have a VGA input, then use a separate monitor that has VGA input for troubleshooting.
  3. On the monitor, change the input to VGA. This sends the visual stimuli information to the workstation monitor instead of sending it to the magnet room. This lets you check that the host PC is relaying visual stimuli correctly.

Topic ID: task_ax4_12h_ytb

NNL SyncBox/Cedrus Lumina Control Box troubleshooting

About this task

ProblemPossible CausesSolutions
Stimulus presentation program does not receive trigger pulses from the SyncBox.
  • The cable between the SyncBox and your PC is not connected properly.
  • The settings in your stimulus presentation program are incorrect.
  • The MR does not send trigger signals to the SyncBox.
  • The settings on the SyncBox are incorrect.
  • Check the cable used between SyncBox and PC.
  • Use this manual as reference and check all settings in your paradigm.
  • Check the settings in the sequence used on the MR console and make sure it sends trigger signals.

Confirm NNL/Cedrus box device is properly recognized:

  1. With all equipment connected and powered up, open a command window on the host PC and become root (su command)
  2. Do a directory listing of /dev (look for ttyCedrusLumina or ttyNNLsync). If these do not exist,
    1. Disconnect the USB cable to the NNL/Cedrus box.
    2. Execute on root the following command: tail -f /var/log/messages
    3. Connect the USB cable to the NNL (USB port 2.0)/Cedrus box (USB port 3.0)
  3. If there is no output then either:
    • the cable is defective
    • the NNL/Cedrus box is defective.
    • Host PC port is defective
  4. If the output on the UI does not explicitly note Nordic or Cedrus then either the port is not the correct USB type or the NNL/Cedrus box is defective.

    If the box is properly reported when connected but otherwise not working check that the speed is configured correctly in the Offline paradigm manager settings > General tab. (Cedrus: 9600 / NNL: 57600)
