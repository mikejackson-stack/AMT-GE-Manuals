Troubleshooting MR Touch

How to change the IP address of the active driver module.

About this task

Check the items below.

Procedure

  1. Hardware:
    • Is power cable plugged in?
    • Is the unit turned on?
    • Is the green LED on the front of the unit illuminated?
    • Is the BNC synchronization cable connected to the unit and to the system?
    • Is the Ethernet cable connected to the unit and to the hub?
    • For newer active driver units (hardware version 3.5 and up), there is a blue LED indicator to show when the unit is awake. Is the blue LED illuminated (if present)?
    • The two green LEDs on either side of the active driver Ethernet jack should be illuminated or blinking. If neither LED is illuminated, the connection to the laptop computer or switch is not working. If using a laptop, connect the active driver to the network switch and check for link lights.
    • If all of the conditions listed above are correct, turn the power off for at least 20 seconds and then turn it back on. Make sure that the green power LED is off prior to turning the unit back on.
  2. Connectivity:
    • Is the touch2d option installed?
    • Open a terminal window on the system and type and enter cd /etc.
    • Type and enter more hosts.
    • A listing of the devices that are connected shows. The MRE unit is usually listed as device 10.0.1.30.
    • Type ping 10.0.1.30. You should see something like the following, which indicates that the system is communicating to the MRE unit. Type ctrl + c to stop the communication test.
      {sdc@mr42}[102] ping 10.0.1.30
      PING 10.0.1.30 (10.0.1.30) 56(84) bytes of data.
      64 bytes from 10.0.1.30: icmp_seq=1 ttl=60 time=0.888 ms
      64 bytes from 10.0.1.30: icmp_seq=2 ttl=60 time=0.418 ms
      64 bytes from 10.0.1.30: icmp_seq=3 ttl=60 time=0.408 ms
      64 bytes from 10.0.1.30: icmp_seq=4 ttl=60 time=0.415 ms
      64 bytes from 10.0.1.30: icmp_seq=5 ttl=60 time=0.421 ms
      64 bytes from 10.0.1.30: icmp_seq=6 ttl=60 time=0.417 ms
      ^C (ctrl c)
      --- 10.0.1.30 ping statistics ---
      6 packets transmitted, 6 received, 0% packet loss, time 5000ms
      rtt min/avg/max/mdev = 0.408/0.494/0.888/0.177 ms
    • If the ping is not successful, go to Configuring the MR Touch active driver and try to re-configure the MRE unit again. If any changes are made to the active driver IP address during the configuration procedure, make sure the IP address in /w/config/mre_comm.cfg matches IP address of the active driver unit. Use gedit to update the IP address in the mre_comm.cfg file as needed:
      • #gedit /w/config/mre_comm.cfg
      • [Active driver IP address] 60.586670 70 6
      • Save the changes and exit gedit
  3. Sleep mode:
    If the MR Touch active driver module fails to communicate after a period of time when it is not being used, it is most likely going into sleep mode. If this happens, download a scan that uses the MR touch imaging option. This will cause the driver to wake up and reset the sleep timer.
  4. If the site network configuration uses DNS servers, it is possible that a conflict could be inhibiting communication in rare cases. Record the DNS server settings in the Network Configuration tab of Guided Install. For troubleshooting purposes, disable DNS in the Network Configuration tab of Guided Install. Perform a system restart and try running an MRE scan again.
  5. Connect to the active driver web interface to test the unit:
    1. Connect the Resoundant active driver to a laptop computer using a known-good Ethernet cable.
    2. First you must configure your laptop with a static IP address beginning with the same network identifier (first byte) as is set on the active driver. The remaining 3 bytes of your static IP address (host identifier) should equal anything other than the active driver's address. Example: the active driver is set to 10.0.1.30 and you set your laptop computer to 10.0.1.31.
    3. Start your web browser application and enter the active driver IP address in the browser URL field to display the active driver main page.
    4. Check the Version number displayed on the main page. If the Version is greater than 22 and less than 22.04, upgrade the active driver firmware using: https://www.resoundant.com/firmware.
      Notice
      Equipment damage risk
      Active driver may become non-functional if an invalid firmware update is attempted.
      Refer to the Resoundant firmware update instructions for valid firmware update paths.
    5. IMPORTANT - for firmware versions 22.04 and higher, verify Add OK to Query shows Enabled on the active driver main page. Failure to enable this setting can result in PSD download errors. If the system experiences PSD programming errors at any time during the troubleshooting, a TPS Reset must be completed to recover.
    6. For firmware versions 22.04 and higher, make sure the driver has been activated. If the driver has not already been registered, register the driver at https://activation.resoundant.com using the username GE and password VS9DLXscG4.
    7. Note down the current values for frequency, amplitude, and duration. Using the web application, edit profile 0. Set the frequency value to 60.1 Hz, the amplitude to 40%, and the duration to 601 cycles (10 seconds at 60.1 Hz). When you click on the screen's change button, the browser will return to the main index page. If you click on the trigger button, you should hear a tone coming from the active driver. The audible range will be a couple feet in a quiet environment. Make sure you wait the entire 10 seconds as an active driver in sleep mode requires about 6 seconds to cycle-up power and become operational. If the active driver produces a sound, restore the frequency, amplitude, and duration settings, connect the active driver to the system and run an MRE scan again. If the system experiences PSD programming errors at any time during the troubleshooting, a TPS reset must be completed to recover.
    8. If the active driver unit pulses successfully with the laptop and web interface but does not pulse during a scan, the problem could be the trigger signal from the MR system Exciter. Use an oscilloscope and a 50 ohm terminator to make sure the active driver is receiving a trigger signal from the exciter through the BNC cable during an MRE scan.
  6. If the active driver pulses but has low (weak) acoustic output, the diagnostic quality of the elastogram could be degraded, inspect the hose between the active and passive driver. Make sure all couplings are firmly seated and there are no cracks or kinks in the hoses. Make sure the passive driver (paddle) has no cracks or damage that would lead to an air leak. If the MR Elastography phantom is available, do the phantom QA procedure to further troubleshooting the condition. Refer to https://www.resoundant.com/phantom-guide. If low acoustic output symptoms persist, replace the active driver unit and repeat an MRE test scan, this method is subjective and will require confirmation with diagnostic images.
